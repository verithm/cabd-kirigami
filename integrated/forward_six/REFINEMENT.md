# 누적 50회 완료 후 중지 — 최신 사용자 지시

2026-11-27 사용자가 공통 40회 이후 각 작업을 누적 50회까지만 완료하고 쉬도록 지시했습니다. 현재 유효한 계획은 여섯 후보×네 작업 모두 20→40→50회입니다. 최종 구간은 10회이며 추가 60회 이상은 실행하지 않습니다. 모든 24개 study를 정확히 50 COMPLETE trial까지 완료한 뒤 결과·개선 추이·감사를 저장하고 제어기가 종료됩니다. 전체 Train 재학습·Test 평가·Inverse 교체는 수행하지 않습니다.

40→50회는 10회 구간이므로 두 번째 20회 정체 구간으로 세지 않습니다. 최종 결과는 사용자 요청 횟수 한도에 따른 종료이며 완전 수렴을 주장하지 않습니다. 원래 100회 계획 프로토콜은 protocol_max100-v2.json에 보존하고, 최신 지시는 user_requested_50_cap.json과 새 protocol.json에 기록했습니다.

```sh
CABD_INTEGRATED_RUNS=/path/to/output python integrated/forward_six/refine.py --max-trials 50 --workers 6
```

이하 내용 중 100회와 두 정체 구간 자동 종료 설명은 사용자 최신 지시 이전의 계획 기록이며 현재 적용하지 않습니다.

# 여섯 후보의 동일 예산 후속 TPE 탐색

2026-11-27 사용자 선택: 일반 MLP만 좁히지 않고 여섯 후보 모두 분류 / 각도·변위 공동 / log10 장벽 / partial 전환 힌지 최대응력의 네 작업을 동일 횟수로 이어갑니다. 과거 각도·변위 단독 및 3출력 회귀는 참고 기록으로 보존하며 후속 대상이 아닙니다.

20회 기존 TPE sampler 상태에서 누적 40, 60, 80, 100회를 점검합니다. 초기 무작위 10회를 재시작하지 않습니다. 최대 100회, 20회씩 같은 누적 횟수로 진행합니다. 각 trial은 기존 형상 Train 분할·5-fold·seed 42·탐색 범위·학습 상한을 유지합니다. Test 점수와 최종 전체 Train 재학습은 포함하지 않습니다.

정체 판단은 최근 20회에서 최고 pooled OOF F1 증가가 0.001 미만(분류), 최고 목적 오차 감소가 상대 0.5% 미만(회귀)인 경우입니다. 각도·변위 목적은 두 출력의 Train-SD 정규화 MAE 평균, 장벽은 log10 MAE, 응력은 MPa MAE입니다. 24개 study 모두 두 구간 연속 정체하면 함께 멈춥니다. 한도에서 개선이 계속되면 한도 내 최고 결과로 보고하며 수렴 완료를 주장하지 않습니다. 이 기준은 탐색 종료용 실무 기준이며 물리 정답·설계 성공 허용오차를 바꾸지 않습니다. 탐색 정체와 내부 학습 최적화의 수렴도 구분합니다.

최초 40회는 이미 별도 실행 중인 분류/회귀 작업들을 기다립니다. `refine.py`는 중복 실행하지 않고 모든 작업의 완료 횟수가 40회가 된 뒤 점검·후속 단계를 수행합니다. 이후는 단일 6-worker pool에서 비싼 GP 분류부터 배치하고 모든 study를 같은 목표까지 진행합니다. 초기 40회는 MLP 4작업과 나머지 후보 6-worker가 일부 겹쳐 일시적으로 최대 10개 단일 수치 스레드가 실행될 수 있습니다. 이 Intel Mac은 물리 8코어/논리 16코어, 메모리 16 GiB이며 GP/MLP/XGBoost 수치 연산 스레드는 각 1개입니다. 시간이 동일하다는 의미는 아닙니다.

결과 루트는 forward-refinement/입니다. protocol.json에 기준과 원본 프로토콜·20회 비교 파일·실행 코드 해시를 보존합니다. 단계마다 모든 검증 예측에서 형상·정답·목적함수·출력별 지표를 재계산하며 comparison_Ntrials.csv, selected_configs_Ntrials.json, audit_Ntrials.json, search_history_Ntrials.csv, search_progress_Ntrials.png를 생성합니다. improvements_to_Ntrials.csv와 stage_N.json에는 최근 구간 개선과 정체 연속 횟수가 있습니다. complete.json은 종료 횟수와 정체/한도 사유를 명시합니다. 이전 20회 비교 CSV/PNG와 선택 설정은 유지하며 원래 study의 best.json은 추가된 전체 시도 중 최고값으로 갱신됩니다.

실행:

```sh
CABD_INTEGRATED_RUNS=/path/to/output python integrated/forward_six/refine.py --max-trials 100 --workers 6
```

이 실행은 이미 시작한 모든 후보의 40회 배치를 기다리는 후속 제어기입니다. study와 sampler·fold 캐시가 보존되어 중단 후 같은 코드·데이터로 재개할 수 있습니다. 재개 시 이미 완성된 stage JSON은 재사용합니다. 원본 모델 코드나 데이터가 달라지면 원본 prepare 검증에서 거부합니다. 후속 예측기나 Inverse 가중치를 자동 교체하지 않습니다.

## GP 분류의 fold 병렬화

GP 분류의 벽시계 시간을 줄이기 위해 모델/학습/지표 코드를 수정하지 않고 parallel_classification.py 실행 래퍼를 추가했습니다. GP 분류의 서로 독립적인 fold를 3개 worker로 계산한 뒤, 원래 tune.evaluate_trial이 동일한 캐시를 읽어 원래 방식으로 목적함수와 결과를 집계합니다. 5개 fold를 모두 마친 뒤 다음 trial을 제안하므로 TPE 순서와 정보는 같습니다. 신경망/XGBoost 분류와 모든 회귀의 계산 함수는 그대로입니다.

기존 40회 분류 실행을 잠시 중단하고 저장된 config·sampler·완료 fold에서 재개했습니다. 새 설정으로 다시 시작하지 않았습니다. 원래 실행 프로토콜은 protocol_sequential-v1.json, 실행 방식 전환은 parallel-execution-switch.json에 보존했습니다. 원래 모델/데이터 SHA는 불변이며 새 제어 프로토콜에는 병렬 실행 코드 SHA도 포함합니다. 순차/병렬 GP의 라벨·확률·지표·목적함수가 정확히 같은지 검증한 테스트를 포함해 총 24개 테스트가 통과했습니다. 커널 최적화 경로의 별도 검증은 optimized-parallel-validation.json에 남깁니다.

추가 단계의 외부 pool은 6개 작업을 실행하며 GP 분류 두 작업만 각각 3개 fold worker를 사용합니다. 따라서 수치 연산은 최대 약 10개 단일 스레드로 겹칠 수 있습니다(초기 별도 40회 작업이 겹치는 구간은 완료 순서에 따라 달라짐). 이 머신의 논리 코어는 16개입니다. fold 시간 합은 병렬 실행의 실제 벽시계 시간과 다르며 속도 벤치마크로 해석하지 않습니다.
